# 光子芯片 Agent Harness 课堂汇报讲稿

对应项目重点版 8 页 PPT。前两页介绍课题，五页介绍现成项目，最后一页总结。计划讲述 7 分 40 秒，尚未实际试讲。页码、标题和建议用时用于对照，不需要朗读。

## 第1页 课题方向 面向光子芯片设计的 Agent Harness

建议用时 55 秒

前面同学介绍了 DAS 系统。我的部分关注这些系统需求进入光子芯片设计流程之后，如何利用 AI 组织设计、仿真和修改。

这里的 Harness，可以理解为围绕智能体运行的一套执行框架。它接收设计目标和约束，连接专业设计工具，保存当前设计状态，并组织结果检查与后续迭代。

沿着图中的流程，Agent 根据需求规划设计方案，调用 CAD 或仿真工具，再把结果交给评价器检查。评价结果随后返回 Agent，帮助它决定下一步动作。

在这个过程中，模型负责规划、解释和决策，专业工具提供结构与数值结果，评价器检查目标是否满足。这个分工，也是理解后面三个现成项目的共同入口。

## 第2页 研究切入点 仿真后的物理诊断与设计决策

建议用时 55 秒

我的研究兴趣主要集中在仿真完成之后。

当仿真结果偏离目标时，Agent 如何判断问题可能出在哪里？它应该修改参数、改变设计策略，还是先补充验证，确认仿真设置是否可靠？

我希望研究的是图中的这条链：从仿真结果出发，形成物理诊断，再选择下一步设计动作。

诊断需要产生可检验的预测。例如，如果认为某个参数影响了性能，就需要预测改变这个参数后，哪些指标可能发生变化，再用下一轮仿真检查这个预测。

如果结果不支持原来的判断，就应该修正假设。目前这还是候选研究问题。已有方法具备哪些相关能力、这种方法能否带来额外价值，需要结合现有项目和后续证据判断。下面介绍三个代表项目。

## 第3页 PhIDO 自然语言到结构化设计与版图

建议用时 60 秒

第一个项目是 PhIDO。这张论文原图把流程分成了四个阶段。

第一阶段是 Interpreter，也就是需求解释。它从自然语言中提取器件、连接关系和参数，并检索相关电路模板。

第二阶段是 Designer。它选择组件、配置参数，生成原理图和结构化的设计描述。

第三阶段是 Layout，利用版图工具完成布局、路由和设计规则检查，输出 GDS 版图文件。

第四阶段是 Circuit Verification，使用 SAX 电路模型进行电路层面的仿真评价。

前两个阶段主要由语言模型 Agent 承担，后两个阶段主要依靠算法和专业工具。它说明自然语言可以进入一个具有中间表示、版图输出和检查环节的设计流程。

需要注意，原图中虽然出现了 FDTD，但相关分支没有进入主发布流程。因此，不能把图中的所有模块都理解为正式基准已经验证的能力。

## 第4页 PhIDO 102 个任务怎样评价设计成功

建议用时 50 秒

介绍架构之后，还需要看它怎样评价结果。

PhIDO 的 benchmark 包含 102 个设计描述，按复杂度分为四级，任务数分别是 23、10、60 和 9 个。

这里展示的是原图中 Gemini-2.5-pro 与 GPT-4o 配合的一组结果。同一级别中，左边的柱子对应 pass@1，右边对应 pass@5。蓝色的 S 表示成功，其余颜色表示流程在不同阶段出现问题。

从图中可以看到，复杂任务仍然存在明显困难。这里主要观察整体趋势，不从柱形图目测推导精确百分比。

更关键的是成功的定义：论文主要检查流程是否没有致命错误，以及是否生成了有效的原理图和 GDS 版图。因此，这些结果证明了结构生成流程的能力，还不能直接说明目标光学性能已经满足。

## 第5页 PICopilot 领域 RAG 与多 Agent 生成设计脚本

建议用时 65 秒

第二个项目是 PICopilot，它主要面向 PIC 设计脚本生成。

图中，Task Planner 先规划任务。功能专用的生成器从工具手册数据库中检索相关内容，再生成代码；Script Synthesizer 合成脚本，Script Evaluator 提供检查反馈。

这里的 RAG，就是检索增强生成：生成代码时参考专业工具手册，帮助模型使用相应接口。

理解这项工作时，需要区分内部反馈和外部评价。内部循环主要采用静态代码检查、自定义检查库和语言模型评价。论文考虑到工具运行成本，没有把逐次真实执行作为内部反馈循环。

外部 benchmark 则另外运行脚本，并与参考输出比较。它包含 48 个任务，每个任务生成 15 次，至少 3 次成功才计为 Solved。作者报告 48 项任务都达到了这个标准。

所以，48 项全部 Solved 并不表示每次生成都成功；脚本功能正确，也不能直接推出器件的物理性能达标。

## 第6页 Kharel 规则与数值仿真驱动的设计闭环

建议用时 65 秒

第三项是 Kharel 等人的自主光子设计工作，它展示了真实数值求解器参与的迭代流程。

原图左边，人类先提供设计目标、约束和初始仿真文件。Agent 修改设计之后，先进行几何预览和规则检查，再调用 Tidy3D 等求解器运行仿真。

随后，评价环节根据数值结果判断候选是否更好，决定保留还是丢弃，并继续下一轮。设计日志则记录整个探索过程。

这项工作说明，已有 Agent 已经能够在显式规则、真实仿真反馈和定量验收条件下进行设计迭代。

但这个闭环依赖正确的初始设置和评价条件。论文中的多物理案例曾出现模态识别、电容处理等设置问题，需要专家修正后才进入后续优化。这也是判断系统能力时必须保留的边界。

## 第7页 Kharel 案例 在求解器反馈中优化波导弯曲

建议用时 70 秒

这张原始结果图展示了波导弯曲设计的迭代过程。

在 400 纳米厚的氮化硅、1550 纳米波长、12 微米弯曲半径和 150 纳米最小特征约束下，作者设置了 50 次仿真的预算。论文报告，圆弧基线的弯曲损耗约为 0.460 dB，最优设计约为 0.109 dB。

看图时，绿色点表示被保留的候选，绿色曲线表示截至当前找到的最优值，红色叉号表示被丢弃的候选。

原图纵轴采用负的 dB 表示，曲线更接近零，意味着损耗更小；右侧文字报告的是正值损耗幅度。

这张图也保留了探索中没有被采用的候选，说明迭代并不是每一步都会改善结果。它支持显式约束和数值反馈能够帮助设计探索的判断。

不过，这仍是作者报告的仿真案例，没有由我们独立复现，也不能把它当作流片测量结果。

## 第8页 总结 已有方法基础与我的研究切入点

建议用时 40 秒

最后总结一下。

PhIDO 展示了自然语言到结构化设计和版图的流程；PICopilot 展示了领域检索与多 Agent 对脚本生成的支持；Kharel 展示了显式规则、数值仿真和定量评价驱动的设计迭代。

它们为课题提供了现成的方法基础，但结构有效、脚本功能正确和数值性能达标，是不同的验证层级。

我的研究切入点是仿真后的物理诊断与动作选择：让诊断形成能被后续结果检验的预测，再考察它是否能提高设计可靠性。

这个方向的具体增益仍需要验证。DAS 可以作为后续复杂应用场景，与小组的系统研究形成衔接。
