### 能判断什么

`INFERENCE`：现有工作已认识比较条件的重要性，也有归档和纠错规则。不能再说它们完全没有 RESULT 或反馈检查。

最强反例是：Agent 或调用代码可能已按指令恢复条件。**本次未发现实际轨迹中发生错误晋升的证据，不宣称这个缺陷已经导致错误。** 原始运行记录、调用链和配置差异尚待核验。

### 对候选方案的意义

`INFERENCE / 建议`：区分两种状态：

- **探索候选**：低成本或条件变更下值得继续检查的方案；结果可用，但还不足以替换已确认的最好设计。
- **确认改进**：与参考设计的要求、评价口径和必要计算条件相容，证据足以支持保留。

只在设置变化影响比较时讨论重新确认，不要求每步增加昂贵仿真。目的是让 Agent 的下一步选择更可靠，而非单纯把日志写得更细。

更简单替代：记录配置版本、固定评价条件、不同条件分表比较；如果足够，就不必为可比性判断另建 LLM 模块。

### 能判断什么

`INFERENCE`：平台期是“当前参数化、尝试范围和反馈条件下的判断”，不是全局最优证明。这组记录支持条件性分析，不足以独立证明宽度、偏移各自的因果贡献，或多模解释正确。

最强反例：已有 Agent 后续确实摆脱了局部平台，因此不能说它不会处理停滞。当前缺少的是对“何时继续、何时转向”的可重复可靠性证据，不是动作首次出现。

### 对候选方案的意义

`INFERENCE / 建议`：先区分三种可能：反馈变化小到无法判断；局部搜索还不充分；当前参数化确实受限。缺乏证据时允许继续获取信息，不强行宣告平台期。

更简单替代：固定范围参数扫描、数值优化器的停止条件和预设多参数化搜索。不能仅凭 Agent 产生解释就排除这些替代。

## 卡 3｜切换策略已有先例，关键是依据与后果

### 已有什么

`AUTHOR CLAIM / E6`：[AutoPhotonicDesign](https://arxiv.org/html/2606.00915v1) §S4.2–S4.3 报告：RF 任务交错探索五类拓扑，记录三次切换；日志指出停滞指标与新家族预期解决的机制。作者还报告 Agent 修复端口域、几何构建和拟合窗口问题。

这里的 RF 综合 FOM 同时含损耗、阻抗和微波折射率目标，**不是谐振器品质因数 Q**。DRC 违规数下降来自另一布线案例，不能替 RF 机理解释作证。

### 能判断什么

`INFERENCE`：已有工作足以反驳“Agent 只能在固定参数中搜索”及“完全不诊断设置”的笼统判断。但“记录了选择理由”不等于理由正确、切换优于继续调参，或同条件可重复。

最强反例：现有框架可能已经足以完成我们目标；新增决策层若只是重复其提示和日志，改进空间很小。论文叙述、现行分支和全部原始轨迹的对应尚未核全，不能断言它缺少某个全局机制。

### 对候选方案的意义

`INFERENCE / 建议`：让每个重要动作明确回答三个问题：

1. 哪条反馈支持现在行动？其他可能原因是否仍成立？
2. 为什么修设置、继续调参或换策略中的这一项更合适？
3. 预期哪个可测指标如何变化？下一步结果若不支持，如何撤回该判断？

这不是要求长篇推理，而是把选择连接到工具可检验的后果。没有后续证据时，动作理由仍是候选解释。

更简单替代：预设拓扑家族搜索或规则路由加优化器。需要说明 Agent 如何在未预设的设置异常或策略权衡中提供增量，而不把使用优化器本身当贡献。

## 综合：本轮把方案收窄到哪里

用户确认的主问题保持不变。`INFERENCE / 候选细化`：

> 在仿真反馈可能不可信、不可比或呈现局部停滞时，Agent 如何以当前证据区分原因，并选择修复设置、继续调参或改变策略，使优化可靠地继续推进？

方法重点是**反馈判别与动作选择之间的连接**，不是只生成可审计报告。类型化调用、字段核对、日志、回退和优化器作为可复用支持层；不假定要新增复杂模块。

暂拟三个方法要点（未实现、未验证、未证明新颖）：

- 区分探索结果与确认改进，避免混用不同评价条件。
- 平台期判断保留条件范围，区分数值问题、搜索不足与参数化瓶颈。
- 动作附最短证据和预期影响，按后续反馈更新或撤回判断。

**H1 修正，H2/H3 仍保留条件性未知。** 当前证据支持问题值得讨论，不能证明拟议方案有效或优于已有方法。工程规则改进也可以是候选，不以“首次物理推理”包装。
