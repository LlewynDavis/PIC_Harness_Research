# Agentic PIC Design：能力边界与评测问题

## 文档定位

- 当前阶段：`Phase 1｜国内外研究现状、发展前景、核心难点和技术路线调研`
- 证据状态：候选理论框架、候选 Research Questions、待验证假设
- 实现状态：未实现 Agent Harness、模型接入、Tool/MCP、仿真闭环或 benchmark

本文件吸收《Theory of Agent: The Science of Internalization and Externalization for LLM-based Agents》及附件解读文章中与本项目相关的思想，用于组织后续调研。附件文章属于二次解读材料；本文不把其中的分类、公式或结论视为已经被本项目证明的事实，也不预设该理论必然成为毕业论文的理论基础。

## 能力边界：模型内化与 Harness 外化

核心问题是：对于光子芯片设计 Agent，哪些能力适合主要由 LLM 参数知识和上下文推理承担，哪些能力必须交给 Harness、Tool、Simulator、PDK、RAG 或 Validator？

这里的“内化”不等于必须重新训练模型，而是泛指能力主要由模型自身参数和当前上下文推理承担。“外化”泛指将知识、计算、状态、控制或验证交给可观测的外部系统。两者不是固定二选一，而是需要根据模型、任务、风险、成本和证据要求研究其合理边界。

### 1. 模型内化候选能力

Phase 1 重点调研以下候选能力：

- 自然语言需求理解；
- 用户意图识别；
- 需求澄清；
- 一般性光子学知识；
- 任务规划；
- 工具选择；
- 仿真结果解释；
- 失败原因推理；
- 设计方案比较。

这些能力是否适合内化，需要考察稳定性、复用频率、模型规模、上下文依赖、可迁移性和错误后果。即使某项能力可以由模型直接完成，也不代表模型输出可以替代可核验事实。

### 2. Harness 外化候选能力

Phase 1 重点调研以下候选能力：

- PDK 参数、材料数据库和工艺约束；
- 模式求解、BPM、FDTD、FEM；
- COMSOL、Lumerical 等专业求解器调用；
- 参数扫描和数值优化；
- GDS 生成和 DRC；
- 物理验证；
- 文件、运行与实验状态；
- 可追溯证据；
- 最新文献和动态知识。

这些能力可能不适合仅依赖 LLM，主要原因包括：

- **精确性要求**：数值、单位、边界条件和工艺规则不能依赖语言生成的近似记忆；
- **实时性与变化性**：PDK、软件接口和最新文献会变化；
- **可验证性**：关键结论需要来源、输入、配置和输出证据；
- **计算复杂度**：全波仿真、优化和参数扫描需要确定性计算资源；
- **高错误风险**：错误参数、版图或物理结论可能产生高代价；
- **可重复性**：科研结论应能由相同输入、版本和配置重算。

“适合外化”仍只是初步判断。后续需要比较外化带来的正确性收益与接口错误、执行失败、延迟、费用和治理成本。

### 3. 自适应工具调用

Agent 研究不能只问“是否拥有工具”，还需要研究“什么时候应该调用工具”。候选决策因素包括：

- 模型不确定性；
- 任务风险；
- 工具成本；
- 时间成本；
- 精度需求；
- 预期工具调用收益。

**候选研究假设 H-01：** 当模型的不确定性或错误风险升高时，Agent 应更倾向于将任务外化给可靠工具。

该假设尚未确定具体决策函数，也没有在 PIC 任务上得到实验验证。后续至少需要定义可观测的不确定性、风险、成本和正确性，并设置 no-tool、fixed-tool 与 adaptive-tool 等对照条件，避免只在失败后解释“本来就应该调用工具”。

### 4. PIC Agent 的知识边界

后续调研需要回答：

- 哪些问题模型可以直接回答？
- 哪些问题必须检索？
- 哪些问题必须调用设计工具？
- 哪些问题必须进行物理仿真？
- 哪些问题必须调用 Validator？
- 哪些情况下应该请求人工介入？

初步示例：

| PIC 任务 | 候选责任边界 | 当前证据状态 |
|---|---|---|
| 自然语言需求理解 | 更偏模型，但关键参数需澄清与结构化检查 | 待验证 |
| MMI 初始几何估计 | 模型/经验公式与工具均可能 | 待对照实验 |
| 最终器件性能 | 必须由适用的物理仿真和验证证据支持 | 原则约束 |
| PDK 参数 | PDK 或有来源的 RAG | 待具体 PDK 验证 |
| DRC | 确定性规则工具 | 不等同 LVS 或 signoff |
| 物理正确性 | Simulator / Validator | LLM 不是真值来源 |

### 5. Epistemic Intelligence / 不确定性感知

建立“认知边界感知”调研子主题，研究 Agent 能否识别：

- 自己知道什么；
- 自己不知道什么；
- 什么时候应继续内部推理；
- 什么时候应搜索；
- 什么时候应仿真；
- 什么时候应请求人工帮助。

重点关注：

- Uncertainty-aware Tool Calling；
- Confidence-aware Planning；
- Failure Detection；
- Escalation；
- Human-in-the-loop。

“置信度”不能直接等同于真实正确率。后续需要研究其校准方式、任务条件、误拒绝与漏调用代价，以及模型自报置信度是否具有预测效度。

## 核心研究问题

以下问题均为候选 Research Questions，不代表全部会进入最终毕业论文：

- **RQ-01：** 光子芯片设计中，LLM 与 Harness 的最佳能力边界在哪里？
- **RQ-02：** 哪些 PIC 设计任务适合模型内化，哪些必须通过外部工具完成？
- **RQ-03：** Agent 能否根据不确定性、风险和计算成本，自主决定是否调用仿真或验证工具？
- **RQ-04：** 自适应 Tool Calling 是否能在保持设计正确率的同时，降低仿真次数、Token、时间或计算成本？
- **RQ-05：** 如何区分模型推理失败、工具选择失败、工具执行失败、物理模型失败和验证失败？
- **RQ-06：** PIC Agent Benchmark 应如何分别评价模型内部能力、外部工具能力以及两者协同能力？

## Agent Benchmark 调研框架

PIC Agent Benchmark 不应只报告最终任务成功率。至少需要调研以下维度。

### A. Internal Capability

- Requirement Understanding；
- Reasoning；
- Planning；
- Clarification。

### B. External Capability

- Tool Selection；
- Tool Argument Accuracy；
- Simulation Execution；
- Retrieval；
- Validation。

### C. Coordination

- 是否在正确时间调用正确工具；
- 是否存在不必要调用；
- 是否漏掉必要调用；
- 是否能利用工具返回结果继续推理。

### D. Reliability

- Failure Detection；
- Error Recovery；
- Hallucination；
- Physical Correctness。

### E. Efficiency

- Token；
- Tool Calls；
- Simulation Calls；
- Runtime；
- Computing Cost。

一个 Agent 最终答对，不代表中间过程正确；一个 Agent 最终失败，也需要区分失败来自模型、Harness、工具、求解器还是验证器。候选评测应保留完整轨迹，并考虑 no-tool、fixed-access 与 adaptive-access 的反事实对照，而不是只比较排行榜分数。

### 候选失败归因

| 失败类别 | 需要观察的证据 |
|---|---|
| 模型推理失败 | 推理输出、约束遗漏、错误假设 |
| 工具选择失败 | 可用工具、选择理由、必要调用遗漏或冗余调用 |
| 工具执行失败 | 参数、接口、权限、超时、返回码和原始日志 |
| 物理模型失败 | 模型适用范围、网格、边界条件、材料和数值收敛 |
| 验证失败 | Validator 规则、输入版本、判定阈值和证据链 |

## 对抗性约束

1. “内化 vs 外化”是宽泛理论框架，解释力强不等于已经具有充分预测能力。
2. 不允许在失败发生后事后解释“这个能力本来就应该外化”；边界假设、判据和评价指标应尽可能在实验前注册。
3. 若采用该理论，需尽量建立可测量变量，例如 uncertainty、task risk、tool cost、correctness 和 latency。
4. 该框架是否真正具有研究价值，必须由 PIC 任务上的对照实验决定。
5. 不因论文或文章与当前课题高度契合，就默认它一定成为最终论文理论基础。
6. 外部工具也会出错；外化不自动等于可靠、可验证或物理正确。
7. 不同器件、设计层级、求解器和 PDK 可能具有不同边界，不能把单一任务结论无条件外推。
